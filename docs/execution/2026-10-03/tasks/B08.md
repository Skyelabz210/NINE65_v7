## Implementation steps

- Preflight both operands against the planned operation and the refresh backend’s input margin; refresh early enough that the input is still admissible.
- For a shared operand squared, refresh at most once. Preserve branch history and avoid recursive refresh loops.
- Use ExactMulEvaluator after preflight. Update counters only after success; return typed failure if refresh cannot provide the next-operation capacity.

## Acceptance criteria

- Deterministic tests exercise no-refresh, left-only, right-only, both and shared-operand cases.
- Refresh failure leaves caller operands unchanged; counters never report a failed refresh as successful.
- A long chain needs no manual refresh request and records actual refresh calls.
