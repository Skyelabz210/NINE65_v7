## A. Decisions that need the owner, not more engineering

These are blocked on a call, not on work.

### A1. Run F-2 step 1?

One exhaustive differential test decides whether a **56× speedup that is also
constant-time** is available. Full scope in `docs/F2_SCOPE_2026-08-25.md`.

Measured on the identical polynomial (secure_192, n=16384, 5 main + 10 anchor):

| path | median | constant-time |
|---|---|---|
| `mod_switch_down_dual` (reconstructs) | 104.316 ms | no — 2.96× |
| `exact_modulus_switch_drop_poly` (lanewise) | 1.867 ms | yes |

The blocker is one **derived, untested** claim: that centering is a no-op modulo
`M'` for the surviving main lanes. Step 1 of the plan settles it and is cheap.
If it refutes, the approach dies and the choice becomes the winding-index route
or fencing the function.

### A2. Adopt `AdjacencyKElim`?

Closes F-3. Built, differential-tested, measured constant-time (1.71 ns/call,
t = 1.10 magnitude / 0.45 order). **Costs capacity: 110 → 96 bits** for
`KElimConfig::Standard`. That is a cryptographic parameter change, which is why
it has no production caller. `crates/nine65/src/arithmetic/k_elimination.rs`.

### A3. Re-cut `secure_128`?

Ships **3 main lanes where n=8192 supports 5** at the same 128-bit claim —
under-provisioned, not incapable. Consequence: it is refused for public refresh
(42 bits of post-refresh `Δ` headroom against the 47 one multiply needs). Either
re-cut it or keep it with the current honest framing.

### A4. Restore GitHub Actions billing

**No workflow has run in this repository since 2026-02-27.** Twelve of thirteen
have never run once. Nothing gates anything. The repo now says so accurately
rather than claiming enforcement, but that is documentation, not a fix — and
re-enabling is an owner action, not a code change.

## D. Do not redo these — they are settled, and re-deriving them wastes a session

Each of these looks like an open question and is not.

- **There is no `add` regression.** Withdrawn in PR #52. `secure_128` was
  *redefined* between February and August (N=4096 → 8192, 3 lanes → 3 main + 5
  anchor), so it does ~3.2× the work under the same name. Measured 0.207 ms at
  `364bd6a` vs 1.04 ms now — a 5.0× ratio against a 3.2× work ratio.
- **The release profile is not a perf cause.** `lto="fat"`/`codegen-units=1`
  measures 1.03 ms against cargo defaults at 0.85–1.01 ms. Overlapping.
- **A `git bisect` over `364bd6a..b03aa4a` converges on `d4c473a` and that is an
  artifact.** Its diff shows the root `Cargo.toml` and `crates/nine65/Cargo.toml`
  as *new files* even though both exist at the `364bd6a` ancestor — a divergent
  re-import, not a behavioural change.
- **The recorded `152.13 ms` public-mul figure is wrong and always was.** At
  `364bd6a` itself, that same N=4096 `secure_128` measures 316.54 ms over three
  runs, while encrypt/add/decrypt all reproduce within 20%. Do not reinstate it.
- **"Depth 50" is not reinstated** — inconsistent with the measured public
  direct-square depths of 2–4.
- **The CT `black_box` barrier in `BarrettContext::borrow_mask_u64` is not on the
  hot path.** Removing it measures 293.91 ms against 281/302 ms with it. It is
  load-bearing for F-1 and must stay.

### Rules this session learned the hard way

- **A cross-time comparison keyed on a config *name* is meaningless once the
  config has been redefined.** Check the shape before comparing.
- **Zero CI check runs is not red CI** in this repo — it is the documented
  state. Do not diagnose it as a failure.
- **Automated review findings need verifying.** A review agent reported five
  "weakened tests" in #49; four were false, and the objections were already
  answered in the tests' own doc comments.
- **A mask idiom is not a guarantee.** `((a < b) as T).wrapping_neg()` compiled
  branchlessly in `k_elimination.rs` and branchfully in `barrett.rs`. Only
  measurement distinguishes them.
- **A two-class timing test whose classes have the same branch taken-rate cannot
  see a branch.** That is why
  `test_ct_dudect_adjacency_k_elim_operand_order` exists alongside the magnitude
  contrast.

## E. Reproduce anything here

```bash
# core op timings, all four configs (generates the README table)
cargo test -p nine65 --test op_timings --release --features allow_insecure \
  -- --ignored --nocapture

# the nine blocking constant-time gates — run SERIALLY; concurrent timing
# tests contend and invalidate each other
cargo test -p nine65 --lib --release -- --ignored --nocapture --test-threads=1 \
  --exact security::ct_verification::constant_time_statistical::<name>

# the two open findings (expected to REPRODUCE their leaks)
#   test_ct_dudect_mod_switch_rescale_fixed_vs_random
#   test_ct_dudect_k_elim_extract_k_operand_magnitude

# full suites
cargo test -p nine65 --lib --release                      # 764 pass
cargo test -p nine65 --test arrow_emission_fhe_gate_matrix --release \
  --features allow_insecure                               # 23/23
cargo test -p exact_transcendentals --release --test cram_gates   # 16/16
cargo clippy -p clockwork-core --all-targets -- -D warnings       # clean
```

`workflow_correspondence::every_ct_timing_test_is_named_by_the_workflow_and_vice_versa`
enforces that every `test_ct_*` is named by exactly one job in
`ct_verification.yml`. It lives in the test suite deliberately: with no CI
running, a gate that exists only in YAML is not a gate.
